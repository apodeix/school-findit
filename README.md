# 어디 있니?

우리 학교 분실물 찾기 — 중학교 구성원을 위한 반응형 웹앱입니다.

운영 주소: https://school-findit.vercel.app

## 사용 방법

- 로그인 전에는 ‘시연 화면’으로 표시된 예시만 볼 수 있습니다.
- 로그인하면 실제 저장된 학교 자료만 표시됩니다. 자료가 없으면 빈 목록으로 안내합니다.
- 학생과 교사 모두 ‘찾기’에서 물건을 검색하고 ‘잃어버렸어요’로 분실 신고를 등록합니다.
- 장소가 기억나지 않으면 ‘모름’으로 입력합니다. 이름·장소·날짜는 필수이고 사진·특징·색상·분류는 선택입니다.
- 물건을 주운 학생은 ‘주인을 찾아요’로 등록한 뒤 선생님께 전달합니다. 인수 전에는 다른 학생에게 공개되지 않습니다.
- 교사는 ‘내 정보 → 인수 대기’에서 실제 물건을 받고 보관 장소를 입력합니다. 교사 직접 등록은 즉시 공개됩니다.
- 분실 신고 상세의 ‘단서 남기기’를 누르면 장소·날짜·시간·내용 입력창이 열립니다. 빈 내용이나 공백만으로는 등록할 수 없습니다.
- 내 글은 ‘내가 쓴 글’, 내 단서는 ‘내가 남긴 단서’에서 다시 확인합니다. 교사도 동일하게 사용할 수 있습니다.
- 교사·최종 관리자는 학생 기능에 인수·보관·반환·신고 처리 업무가 추가됩니다.
- 하단 메뉴는 홈·찾기·등록·내 정보 구성을 유지합니다. 교사 인증과 인증코드 설정은 내 정보 안에서만 표시합니다.

## 도움 포인트

- 학생 등록 습득물을 실제로 인수하면 3점입니다.
- 분실 신고 작성자가 유용한 단서를 ‘도움 됐어요’로 확인하면 단서 작성자에게 1점입니다.
- 같은 신고의 같은 작성자에게는 단서 개수와 관계없이 한 번만 지급합니다.
- 거래 생성·인수 상태 변경·알림을 서버의 Firestore 트랜잭션으로 처리합니다. 동시 클릭도 중복 지급되지 않습니다.
- 취소 시 거래는 남기고 총점과 배지를 다시 계산합니다. 같은 활동에는 재지급하지 않습니다.
- 총점과 거래는 본인, 담당 교사, 최종 관리자만 확인합니다. 순위표는 없습니다.
- 배지 기준은 `lib/rewards.ts`의 `BADGE_CRITERIA`에서 변경합니다.

## 알림과 관리

단서 등록, 유사 습득물, 인수, 보관 장소 변경, 게시물 상태, 포인트 지급·취소를 앱 알림함에 저장합니다. 읽은 알림도 삭제되지 않습니다. 알림을 누르면 관련 물건으로 이동하며 삭제·숨김된 물건은 열람 불가를 안내합니다.

최종 관리자는 잘못 보낸 알림을 ‘취소’로 바꿀 수 있습니다. 취소자와 시각을 보관하고, 이미 읽은 사용자에게도 취소된 안내임을 표시합니다. 별도의 학교 전체 공지 작성·발송, 이메일과 웹 푸시는 현재 범위에 포함되지 않습니다.

신고·숨김·삭제·상태·포인트·권한 변경은 관리 기록을 남깁니다. 삭제는 물건을 공개 목록에서 제거하는 소프트 삭제입니다. 교사는 임시 숨김, 최종 관리자는 숨김 해제와 다른 사람의 자료 삭제를 할 수 있습니다.

## 교사 인증 보안

신규 계정은 학생입니다. 기존에 지정된 최초 관리자만 예외입니다.

- 최종 관리자만 코드를 설정합니다. 새 코드는 12~32자이며 영문·숫자·기호 중 두 종류 이상을 조합해야 합니다.
- 코드는 서버에서만 확인하며 임의 salt와 scrypt 해시를 저장합니다. 원문·해시는 학생에게 전달하지 않습니다.
- 계정별 15분 동안 5번 실패하면 추가 시도를 차단합니다.
- 교사 권한을 회수하면 같은 인증코드로 즉시 재인증할 수 없습니다. 서버는 모든 변경 요청에서 최신 역할을 다시 읽습니다.
- 기존 SHA-256 방식 코드는 신규 인증에 사용하지 않습니다. 최종 관리자가 새 코드를 한 번 설정해야 합니다. 기존 교사의 인증은 유지됩니다.
- 다른 일반 교사를 최종 관리자로 지정할 수 있습니다. 본인 또는 기존 최종 관리자의 권한 회수는 지원하지 않습니다.

공유 코드는 교직원에게만 전달해야 합니다. 현재는 사용자의 요청으로 확인된 Gmail 계정을 시험용으로 허용합니다. 실제 학교 운영 전에 학교 도메인을 확정하고 Gmail 임시 허용을 종료해야 합니다.

## 기술과 저장소

- Next.js/Vinext 정적 내보내기, React, TypeScript, Tailwind, Shadcn UI, Lucide
- Vercel의 `api/app.ts` 서버 함수 + Firebase Authentication + Cloud Firestore
- Firebase Admin 13.6 계열과 Firestore 7 계열 사용. Admin 14의 ESM 의존성은 현재 Vercel 런타임에서 호환성 문제가 확인되었습니다.
- 사진은 긴 변 1,000px 이하 JPEG, 데이터 URL 450,000자 이하로 압축해 Firestore에 저장합니다. 목록에서는 사진을 제외해 조회하고 화면에 보이는 사진만 별도 요청합니다.
- Blaze 업그레이드나 결제 연결은 하지 않습니다. 이 사진 방식은 소규모 시험 운영용이며 이용량이 늘면 전용 저장소 이전이 필요합니다.
- Firestore의 변경 시각 문서로 새 자료를 갱신하며 연결이 끊기면 화면 복귀·수동 새로고침·1분 간격 조회로 보완합니다.

주요 컬렉션은 `users`, `items`, `clues`, `notifications`, `reports`, `reward_transactions`, `audit_logs`, `app_settings`, `verification_attempts`, `notification_jobs`입니다. 기존 `teacher_verifications`는 기존 교사 이관에만 사용합니다.

## 배포 설정

Vercel은 `dist/client`와 `/api/app` 함수를 함께 배포합니다. `main`에 푸시하면 운영 배포를 시작합니다. `.vercelignore`로 개발 산출물·환경 파일·시험 파일을 배포 업로드에서 제외합니다.

`.env.example`의 Firebase 공개 환경변수와 서버 전용 `FIREBASE_SERVICE_ACCOUNT`를 설정해야 합니다. 비공개 키는 `NEXT_PUBLIC_` 변수, 소스, GitHub, 대화에 넣지 않습니다.

현재 서버 전용 서비스 계정은 Firestore 자료 접근과 Firebase 사용자 확인에 필요한 권한만 가지고 있으며 Vercel Production의 민감한 환경변수로 등록되어 있습니다. Preview에는 자동으로 비공개 키를 전달하지 않습니다.

`scripts/connect-server.mjs`는 소유자의 기존 CLI 로그인을 이용하는 일회성 설정 도구입니다. 기본 실행은 계정 존재 여부만 확인합니다. `--provision`은 별도 승인 후에만 사용하며 비공개 키를 디스크에 남기지 않습니다.

`firestore.server.rules`는 직접 데이터 접근을 차단하고 변경 시각 문서 조회만 허용합니다. 모든 실제 자료 읽기·쓰기는 서버에서 계정, 학교 접근 정책과 역할을 검증합니다.

```bash
corepack pnpm dlx firebase-tools@15.8.0 deploy --only firestore:rules,firestore:indexes
```

학교 설정은 비공개 `app_settings/security`의 `allowedEmailPattern`, `allowGmailTesting`, `initialAdminEmail`을 사용합니다. 학교 도메인 변경은 계정 잠김을 방지하도록 관리자 계정도 함께 확인해야 합니다.

## 개발·검사

사용자는 설치 없이 운영 주소에서 사용하면 됩니다. 아래 명령은 개발·검증용입니다.

```bash
corepack pnpm install --frozen-lockfile
corepack pnpm exec tsc --noEmit
corepack pnpm exec tsx --test tests/domain.test.ts tests/rewards.test.ts tests/teacher-code.test.ts tests/navigation.test.ts
corepack pnpm build
```

`pnpm dev`는 화면 개발용입니다. 실제 API는 Vercel에서 함께 실행해야 하므로 프런트 개발 서버만으로 저장 기능이 동작한다고 안내하지 않습니다.

`tests/backend.integration.ts --live-school-findit`는 명시적 승인 하에 실제 저장소에서 고유한 가상 시험 자료만 생성·정리하는 통합 검사입니다. 실제 사용자 자료는 변경하지 않습니다. 코드 변경 후에는 입력·권한·중복·반환·알림을 검사하고 운영 배포의 완료 상태와 API 응답을 별도로 확인합니다.

Windows Node 24에서는 빌드 산출 후 종료 시 `UV_HANDLE_CLOSING` 오류가 발생할 수 있습니다. Vercel Linux 빌드 결과와 구분해 보고해야 합니다.
